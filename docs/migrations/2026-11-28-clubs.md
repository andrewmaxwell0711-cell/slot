# Additive migration: Clubs and team play

**Status:** applied automatically on local SQLite and in unit tests. **Not applied** when a hosted `DATABASE_URL` is set, unless `ALLOW_SCHEMA_MIGRATE=1`.

**Do not run this branch against the production Render Postgres** (`crystal-casino-db`). This staging branch must not be merged to `main` (which auto-deploys) until sign-off. Never set `ALLOW_SCHEMA_MIGRATE=1` on production.

## Purpose

Social clubs (Huuuge / Slotomania style) with a weekly team goal. Members' settled spins and wins add progress through the v10 `events.on_play` hook. Reward tiers pay **house-issued promotional virtual coins** to every eligible member. Coins have no cash value, cannot be redeemed, and **cannot be transferred between players**. Club rewards are not taken from the game house pool, so they cannot change slot RTP.

Club chat, if used, stores a **preset phrase id only** — never free text — so there is no player UGC to moderate.

## SQL (additive, safe)

```sql
CREATE TABLE IF NOT EXISTS clubs (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    emblem TEXT NOT NULL,
    visibility TEXT NOT NULL,
    invite_code TEXT NOT NULL,
    leader_id TEXT NOT NULL,
    created_at TEXT NOT NULL,
    disbanded_at TEXT
);
CREATE UNIQUE INDEX IF NOT EXISTS clubs_invite_code ON clubs(invite_code);

CREATE TABLE IF NOT EXISTS club_members (
    club_id TEXT NOT NULL,
    player_id TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'member',
    joined_at TEXT NOT NULL,
    PRIMARY KEY (club_id, player_id)
);
CREATE UNIQUE INDEX IF NOT EXISTS club_members_one_club ON club_members(player_id);

CREATE TABLE IF NOT EXISTS club_week_progress (
    club_id TEXT NOT NULL,
    week_id TEXT NOT NULL,
    player_id TEXT NOT NULL,
    spins INTEGER NOT NULL DEFAULT 0,
    bet_coins INTEGER NOT NULL DEFAULT 0,
    win_coins INTEGER NOT NULL DEFAULT 0,
    points INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (club_id, week_id, player_id)
);

CREATE TABLE IF NOT EXISTS club_reward_claims (
    claim_key TEXT PRIMARY KEY,
    club_id TEXT NOT NULL,
    week_id TEXT NOT NULL,
    player_id TEXT NOT NULL,
    tier INTEGER NOT NULL,
    amount INTEGER NOT NULL,
    created_at TEXT NOT NULL
);
CREATE UNIQUE INDEX IF NOT EXISTS club_claims_player_week
    ON club_reward_claims(player_id, week_id);

CREATE TABLE IF NOT EXISTS club_chat (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    club_id TEXT NOT NULL,
    player_id TEXT NOT NULL,
    phrase_id TEXT NOT NULL,
    created_at TEXT NOT NULL
);
```

- No existing tables or columns are altered or dropped.
- `club_reward_claims.claim_key` is `club-week:{week_id}:player:{player_id}` — one claim per player per week.
- The extra unique index on `(player_id, week_id)` stops a player from claiming twice by leaving and joining another club in the same week.
- Leaving a club does not delete that week's progress rows (history is kept; the player simply stops adding new points until they rejoin).
- Disbanding sets `disbanded_at`; club rows are not hard-deleted.

## How it is applied

`clubs.ensure_schema(conn)` is called from `ledger.init_db()` only when:

1. `ALLOW_SCHEMA_MIGRATE=1`, or
2. `DATABASE_URL` is unset (local SQLite / tests).

To apply later on a **non-production** staging database after sign-off, set `ALLOW_SCHEMA_MIGRATE=1` and start the app, or run the SQL above once as a migration.

## Rollback

Drop in dependency order. This does not affect balances already credited, purchases, or game math.

```sql
DROP TABLE IF EXISTS club_chat;
DROP TABLE IF EXISTS club_reward_claims;
DROP TABLE IF EXISTS club_week_progress;
DROP TABLE IF EXISTS club_members;
DROP TABLE IF EXISTS clubs;
```

Already-paid club rewards stay in `ledger_entries` (`kind = 'club_reward'`) and player balances. Do not reverse them as part of a schema rollback.
